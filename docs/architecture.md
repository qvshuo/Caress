# 架构契约

## 职责与身份

Emby 独占媒体、元数据、人物和图片。Caress 识别番号，按配置查找来源，加工后通过 REST 写回。不挂载或修改媒体源，不写 NFO，不建立第二套媒体库、独立元数据编辑器、元数据历史或账户体系。SQLite 仅保存设置、处理记录、当前或最近一批任务及来源冷却，不提供导入或迁移框架。Compose 以非 root 运行，命名卷挂载到 `/data`。

番号只从视频或 STRM 文件名主干识别。末尾 `-C`、`-U`、`-UC`、`-cdN` 是文件属性，不决定发行分类。不依赖父目录，也不模糊匹配或重命名。

来源按四类配置顺序查询，首次精确命中即停，不拼接其他来源字段。FC2 和纯数字格式直接分类，其余使用静态完整前缀表，未知或冲突保持 UNKNOWN。前缀表只影响查询顺序，不参与作品身份或 DMM CID 验证。用 `scripts/catalog.py` 手动根据公开 JavDB 有码及 AVSOX 无码记录建表。正式名单经核验发生变化后才更新 `updated_at`，不在线学习或更新。

查询格式转换不能用于身份比较。已确认的别名可规范化，数字番号中的下划线与连字符仍有区别。来源适配器仅凭明确证据恢复命名空间并核验候选，Scraper 统一核对最终番号。DMM 不猜测数字命名空间。共享来源限速与冷却，区分排队和请求超时。Scrapling 读取网页，httpx 用于 REST 和图片，FlareSolverr 处理浏览器挑战。

## 加工与写回

Gfriends Filetree 是演员别名、标准名称和头像地址的唯一数据源。标准名来自实际图片文件名，未匹配时保留来源原名。翻译只处理标题与简介，保护原名和标准演员名，失败保留原文。使用 Emby 原始标题字段，不另存原始数据快照。

关联 Item 单独核验归属并去重。写前重新核验服务器、Item 身份和所选库，读取完整 DTO、有限合并，并回读验证元数据与图片。保留非受管属性、人物和图片，只改 `caress` ProviderId，不改锁定字段。人物头像按回读的 Person ID 写入。

- **刮削缺少的元数据**只补现有缺失项。文件名或番号形式的占位标题可替换，文件属性标签可追加。保留有效字段、人物名单、Primary 和已有头像，按像素去重追加背景图。
- **替换所有的元数据**需确认。本次有效来源结果替换受管字段，缺失项清空，标签按来源和文件属性重建。只有成功准备的新封面及头像可替换旧图。整个 Backdrop 集合受管，包含自定义背景。新图全部回读通过后才删除旧图，无候选时清空，获取或准备失败时保留旧集合。
- 来源失败或标题为空时不写入 Emby。需写入的封面准备失败则停止，背景和头像失败保留警告。明确拒绝的图片请求不计入变更，结果不明或回读失败时如实报告可能的部分写入，不模拟回滚。失败或背景图尚未补齐仍可重试，无变更时按跳过处理并保留原处理历史。

批次使用开始时的全局配置快照，追加项只指定模式和来源。单队列内每次提交最多四并发，同番号复用加工，同 Item 写入互斥。同 Item、模式和来源的未完成请求去重。取消停止待处理项并结算已经开始的写入，重启标记中断且不自动续写。

## 界面与会话

搜索、筛选和翻页共用只读列表投影。重新进入列表、主动刷新或批次结束时重读，设置变化使投影失效。详情实时读取。列表与详情共享进度，空闲不轮询，过时响应不能覆盖新状态。同一作品的后台刷新保留打开的裁剪和看图会话。

手动裁剪优先使用 Emby 横向背景，必要时获取来源原图。新图及初次预览成功后才替换会话，失败保留原图和选框。修正 EXIF 方向，固定 2:3，预览只编码缩略图，保存只更新 Primary，不改刮削记录。关闭、保存、配置变更或过期时清理会话。

图片代理只读取所选库中的作品或其关联人物，人物图片仅允许 Primary。密钥只在服务端使用，禁止写入日志或将 Emby 请求凭证转发到外部。来源与可信 Emby 的上游 JSON 错误保留原始内容。
