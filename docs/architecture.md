# 架构契约

## 数据流与职责

Emby 所选库分页读取 → 文件名识别番号 → 检查当前补齐需求 → 来源按优先级精确命中 → 翻译/演员匹配/图像加工 → 按 Item 写入 Emby → 回读验证 → 记录结果。

媒体与完整元数据不落本地库。列表响应提供当前查询的轻量导航顺序；详情通过 ParentId/Ids 定向校验范围，再按 Item ID 获取最新数据。直达详情没有列表上下文时不猜测相邻项。离线明确报错，不展示旧数据。

模块边界见 AGENTS.md。Emby 是持久化目标，临时加工文件只活在当前批次或裁剪会话中。

`docker-compose.yml` 使用 Docker 命名卷，Caress 数据持久化于 `/data`，FlareSolverr 配置持久化于 `/config`；无需挂载 Emby 媒体目录。

## SQLite

| 表 | 内容 |
| --- | --- |
| options | 当前设置，密钥仅在服务端 |
| rules | 番号分类与演员匹配规则，首次使用从随包数据初始化 |
| scrapes | 服务器/Item 主键、创建时间与番号身份、历史成功、最近结果/原因及成功来源 |
| batch | 唯一当前/最近批次，Item 进度、写入边界与必要失败原因 |
| cooldowns | 来源及请求主机的限速冷却 |

事务保护写入。成功历史与最近结果独立，原始失败与取消状态保留；展示合并为待处理、已处理、失败、不支持和运行时的处理中。列表按不支持、失败、已处理、待处理排序，同组按番号升序，筛选、分页和详情导航共用该顺序。补齐依据 Emby 当前内容，不按历史成功跳过。重启清理中断状态，保留确认过的成功。缺席 Emby 的 Item 不触发破坏性删除。

## 执行与资源

一个执行队列允许运行中追加请求，每次提交保留自己的操作模式与来源，按提交顺序执行；每次提交内部默认四并发，同番号复用一次刮削与翻译，每个 Item 独立写入。相同 Item、模式与来源的未完成请求去重。取消未开始写入的处理和全部等待项，已开始的写入完成后回读，已完成结果保留；重启标记中断，不自动续写，不保存历史任务列表。

开始时读取所选库 Movie ID 集合，追加请求复用该集合；关联 Video 或新出现的 Item 单独通过 Movie/Video 范围查询验证。展开关联时逐项校验、去重，越界/无法确认项单独跳过。慢速加工结束后再次复核归属与身份。每个 Item 的冲突写入互斥。

Service 持有 Emby 连接池，请求与批次仅租用；首次连接验证服务器身份。配置变化切换新池，活动租用结束才关闭旧池。服务关闭先取消批次，再关闭连接和 SQLite。

来源独占、限速、冷却和有限网络重试独立于作品并发。顺序命中即停，不做全来源预抓取。翻译只处理标题/简介，每批用无害文本验证，每次一个请求，失败保留有效原文；演员身份有歧义时不猜测。头像锁内处理，已有头像不覆盖，每人物每批最多两次尝试，仅成功或确认无需处理才记完成。

JavDB 作品通过网页定位；演员优先使用作品页中关联的 ID，否则从演员网页精确匹配候选，再通过免 JWT 的演员详情 API 核对身份与类型。候选仍有歧义时保留原名，不保存猜测结果；不请求需要登录 JWT 的搜索及作品详情 API。

## Emby 写入

写前读取 Emby 当前完整数据，只修改 Caress 支持的元数据字段。来源缺失的值不清空，其他字段原样保留。

scrape 只填缺失的有效标量或空集合，保留已有 Actor/Director 集合与 Primary；标题若与视频文件名主干或规范番号完全相同，视作文件名占位标题，允许补齐。force 有有效来源值才替换受管字段。标签在 force 中非破坏性合并，scrape 只补空标签集合与文件名标识。背景图只能按内容去重追加，不推测来源图片是否完整。预检查用于避免无意义抓取，写前重新读取并按模式合并。最终无变更时不伪造成功写入，批次记跳过并恢复原处理记录。

元数据和图片均回读验证；HTTP 成功不代表持久化。Emby 没有跨 HTTP 请求事务，失败可能已部分写入，必须准确标记并允许安全重试。

图片上传使用实际 MIME 和 base64。Primary 可明确替换；Backdrop 以像素内容去重后追加，不通过不稳定索引或 tag 判断相同，不删除未知归属图片。同 URL 的原图只抓取一次，来源摘要仅在当前加工结果内复用；Primary 在确实需要写入时才裁剪，同番号并发复用一次临时裁剪结果。已有图片逐张比较，RGBA 条带摘要降低内存峰值，不建立持久指纹表。

背景图仅使用实际为横向的封面或剧照；没有合适候选不视为失败，下载失败保留非致命警告。需要写入的 Primary 准备失败及任何上传/回读失败仍报告失败，不能把未确认写入计为成功。无永久图片失败缓存，下一次手动操作可再次尝试。

## 裁剪与安全

裁剪原图优先用 Emby 横向背景，按需重新查询 JAV 来源；不把 Primary 假装当作完整原图。无 EXIF 变换时保留原编码，必要时纠正方向。初始居中选框；YuNet 按需加载，先缩图再检测。固定 2:3，无拉伸，最终 PNG 直接上传目标 Primary；不改变背景、人物或刮削记录。封面上传并通过回读验证后即视为保存成功；作品详情随后独立刷新，刷新失败不改变保存结果。

图像限制为 32 MiB、40MP，在解码前限制像素，使用 Pillow 一次实际解码验证。裁剪只保留一个活动会话，新原图及首次预览成功后替换旧会话；来源获取串行，随机 token 隔离旧请求，十分钟惰性过期，关闭/保存/配置变化时清理，无后台定时器。临时文件在批次结束清理。

API 设置接口不返回密钥；Emby 和翻译 API Key 通过请求头传输，不记录请求头。来源和可信 Emby 的 JSON 错误原样显示，不做通用字段脱敏；固定界面文案使用中文，内部日志使用英文。图片只代理固定 Emby 地址、合法 Item ID、Primary/Backdrop 和有限索引，禁用重定向，不将密钥放入 URL。不提供任意路径读取、媒体操作或任意目标代理。

用户自行关闭 Emby 在线提供者；本地 NFO 读取、自动扫描、手动刷新和重新入库仍遵循 Emby 自身语义。

已配置时设置页自动读取媒体库，连接按钮用于初次连接与手动读取；输入改变或离开页面时取消旧请求，不让旧响应覆盖当前表单。图片代理复用客户端已验证的内容与 MIME，不重复完整解码；裁剪最终 PNG 超过 32 MiB 时拒绝保存，不缩小原像素或降低质量。

图片读取按所选库验证 Movie/Video，Person Primary 必须由该库 Movie 的 People 精确关联确认；不建立图片访问缓存。批次每个 Item 在外层 finally 结算同番号引用，最后使用者负责取消并等待未结束的加工、释放临时文件。图片方向键仅在浏览区域生效，失败重试使用新的请求标识，URL 变化时重置失败状态。

作品列表与详情共用队列进度，每项保存各自的模式与来源，来源名称统一显示；取消详情不重复显示状态。连续三次轮询失败时在进度内提示，恢复后清除。单项结果更新列表状态，当前详情处理结束后重新读取 Emby；队列结束刷新列表，不为进度轮询重复读取全库。跳过原因、失败和非致命警告分别呈现。

设置仅包含 Emby、翻译与四类来源优先级；来源地址和 FlareSolverr 地址由代码内置，不提供自定义入口。非法来源顺序直接拒绝，不自动修正。图片失败状态以 URL 为 React key 重置，重试标记仅用于绕过失败缓存。
