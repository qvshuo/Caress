# 最终正确性与性能打磨

版本 1.7.0；基于 `refactor/work-base-ui` 的 `2923286`。保持两页式 UI、Emby 唯一事实来源和最小 SQLite 结构。

## 根因与修复

| 问题 | 根因与最终行为 |
| --- | --- |
| 关联 Item 越界 | 原展开只验证根 Item。现在用批次初始所选库集合逐项校验、去重；越界/无法读取项单独跳过并说明，不阻断合法项。写前再次定向复核当前归属和身份。 |
| 详情重复扫描 | 导航依赖完整库投影。列表响应附带轻量顺序，浏览器按当前查询结果前后切换；详情只做目标归属查询与最新完整 Item 读取。 |
| 图片重复连接与身份查询 | 每请求创建客户端。Service 持有池和首次验证，详情/图片/裁剪/批次租用；配置变化切换新连接，活动租用结束才关闭旧池。管理员发现也加锁去重。 |
| 背景去重开销 | 来源摘要在每个 Item 上重复计算，RGBA 比较产生整图临时内存。来源摘要按批次加工结果复用，已有图逐张下载；同字节摘要复用，条带 RGBA 摘要和顺序验证降低峰值。保留像素级正确性，不用图片索引/tag猜测相同。 |
| 历史成功后失败混淆 | 历史成功与最近结果缺少明确展示。保留原 succeeded_at/status，派生“重刮失败”，普通刮削仍跳过；取消独立呈现。记录写入边界，取消/重启准确说明尚未开始或可能部分写入。 |
| 头像失败被记完成 | people_done 提前写入，下载层还缓存错误。完成标记移到成功/已有头像/确认无图之后；锁内去重，每人物每批最多两次尝试，临时错误不缓存。 |
| 原图无条件 PNG 化 | 无 EXIF 变换也转换。普通 JPEG/PNG/WebP 保留原字节；必要的方向纠正才转 PNG，坐标与浏览器一致；先限制像素再解码。YuNet 先缩图再建数组。 |
| 边界细节 | AdditionalParts 不再先补读每个详情再重复补读；新身份不继承旧来源；图库边界按钮保留焦点，方向键继续有效；删除未使用 Confirm 类型。 |

未新增数据库表、持久图片指纹、媒体清单、缓存框架、依赖或兼容 API。API 主要变化为列表增加 `order`，详情不再接受导航查询、不返回导航；裁剪原图响应使用实际 MIME。同步更新前后端，无长期双轨。

## 最终 Review 与限制

范围验证、完整 DTO 合并、Item 互斥、SQLite 事务、写后回读与部分失败报告均保留。没有 NFO 写入；没有主动修改 LockData/LockedFields；没有新账户体系、任意 URL 代理或前端密钥。版本统一为 Python/Web/README 1.7.0，源代码发布继续走匹配标签的既有工作流。

Emby 没有跨请求事务，归属复核与实际写入之间仍有服务器并发变更窗口，无法声称原子授权或外部回滚。关联项若未被所选库 API 确认，保守跳过。图片 tag 不足以证明跨图片内容相等，已有背景仍须下载做内容比较；没有伪造轻量去重。导航保持打开列表时的顺序；没有列表上下文的直达详情禁用相邻导航，不猜测顺序。新字段/标题搜索需刷新列表后更新顺序。

本轮没有重新对十个 JAV 来源逐一联网探测、没有破坏性中断真实服务器或大规模压力测试；来源协议保持原实现，既有测试覆盖仍通过。此前完整刮削、分集/多版本、NFO 读取行为等联调记录见 [重构交付](delivery.md)。
