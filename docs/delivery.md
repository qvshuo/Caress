## 数据库与升级

SQLite 仅含 `options`、`rules`、`scrapes`、`batch`、`cooldowns`。不保存影片 DTO、媒体清单、候选、手动字段状态、图片库、指纹和任务事件历史。处理记录核对服务器、Item ID、创建时间和番号；Emby 手动编辑不触发刮削或翻译。强制处理失败显示最近失败，但保留历史成功时间，普通刮削仍保护此前成功作品。

旧库结构不就地修改。一次性导入工具先备份，再在临时数据库中验证并事务导入，成功后原子发布到新路径，不覆盖已有目标。迁入连接、来源、翻译和可靠匹配规则。旧成功记录无法证明当前 Item 身份及完整写入，因此不继承；首次批次需人工核对选择。未向现存业务影片发送测试性元数据或图片写入请求。

## 最后一轮 Review 与边界

- 所有权：作品/图片均读 Emby，无静态旧元数据后备；Caress 写入只来自明确任务或裁剪操作。
- 一致性：SQLite 事务、Item 写互斥、身份复核、元数据及图片回读；如实报告跨请求部分成功，不虚构外部回滚。
- 资源：图像 32 MiB/40MP 上限在解码前检查尺寸；临时文件随编号完成/批次退出清理；裁剪会话四个、十分钟过期，原图重取有时限；CPU 图像工作移出事件循环。
- 请求量：来源命中停止，同番号共享加工；背景图每次读取一遍签名后去重，避免对每张待上传图片重复全量回读。只轮询活动批次，无全库定时轮询。
- 前端：仅作品/设置，元数据表单及通用图库已删除。移除闲置组件、hooks 和 sonner 后公共生产 JS 约 323 KiB，裁剪器独立懒加载。
- 安全：API Key/Cookie 不返前端，验证错误不回显输入；图片代理固定服务器目标，Emby 请求不跟随外部重定向；无任意文件或通用代理接口。
- 尚有限制：网络来源受地区、会话、限流和站点变化影响；未做长时间压力测试或物理断网实验，部分 HTTP 写入失败由自动化模拟。手动 Emby UI 的全部控件未逐一人工点验。不能证明完整的背景图必须由用户检查，不能从已裁剪 Primary 恢复。
- Emby 原生扫描、NFO、手动刷新及重新入库有自己的更新语义。关闭在线提供者不等于冻结元数据；Caress 不会代为改变锁定。
