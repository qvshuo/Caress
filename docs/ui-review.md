# UI 审查与交互恢复

2026-11-09，按用户提出的八项问题修整。使用 Damir Sokolovsky 的 [unslop](https://heydamir.design/unslop) 审查方法（CC BY 4.0），沿用既有系统字体、中性色、React/Tailwind/Base UI 组件，不引入新框架或装饰图片。

## 审查结论与方向

问题集中在交互退化和信息密度，并非需要重做品牌：列表被扁平多行替代后失去列对齐；默认大图降低查找密度；视图切换和分页被弱化；原生 select 与成熟控件不一致；来源排序变成冗长按钮列表；翻译位置过后；测试连接混入读取媒体库；打开手动裁剪会先访问来源并加载人脸处理。

产品方向为面向 Emby 的刮削与封面加工工具；气质克制、准确、紧凑；视觉沿用中性工具界面；丰富内容来自作品封面；番号列固定对齐，控件交互保持统一。依据用户明确给出的恢复方向直接实施，不额外更换视觉风格。

## 裁剪响应

此前获取原图会先查 JAV 来源；来源等待、限速或挑战可能使打开操作拖长到 45 秒，随后才尝试 Emby 背景图。初始预览还会加载 YuNet。

现在先直接读取 Emby 的横向背景图，立即生成居中 2:3 选框。人脸裁剪仅在点击按钮后加载 YuNet；“刷新”由用户显式触发，取图不再创建翻译/演员处理器。没有可用背景时仍需访问来源，保留超时和明确错误，不把已裁剪 Primary 当作完整原图。

## 第二轮交互打磨

按用户后续十六项反馈与导航、刷新补充统一完成：

- 作品、设置等宽；仅保留表格，搜索为“番号或标题”，保留成熟列控制与分页。

- 详情顶部左侧“← 上一个作品”、中间“返回”、右侧“下一个作品 →”；按当前搜索/筛选顺序，边界禁用，跨页返回保留位置。
