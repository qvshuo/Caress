# Caress

## Runtime and delivery
- Use Docker Compose for builds, deployment and restarts. Python 3.15/pip; local Python checks use `uv run --no-project --python 3.15`. Keep environments, caches, checks and backups outside the repository.
- `caress/` owns sources, processing, runtime and API; `caress/web/` uses strict React/TypeScript, Tailwind CSS 4, shared shadcn/ui and Bun. Python serves the static build; production has no frontend runtime. `emby-plugin/caress/` owns Emby providers.
- Use Caress for product branding and lowercase caress for packages, assembly, providers, protocol and NFO identifiers. Python, web and plugin versions are 1.6.1. C# changes must rebuild tracked `emby-plugin/caress.dll`.
- Track `bun.lock`, the plugin DLL, used YuNet model and license. Test suites, frontend tests, plugin verification and fixtures stay outside the repository; production builds must work without them. Exclude dist, caches, real settings, databases, logs, backups and screenshots. Ship only `docker-compose.example.yml`; real Compose/data stay untracked. Verify both the complete program and the full candidate file set, including untracked renamed sources.
- Keep README.md as a concise Chinese quick start, grounded in current behavior. Distinguish container paths from host paths, document fill/refresh/portrait semantics, and describe the Emby plugin as a local-file reader. Compose mount changes require container recreation.
- Defaults: port 9307, settings `/data/settings.json`, metadata `/data/metadata`, FlareSolverr `http://flaresolverr:8191/v1` (blank disables it). Validate bundled runtime resources during build and startup.

## Data and actions
- Product scope: scan → fetch candidates → preview/select → save NFO/images → Emby. No browser import, comparison matrix, probe/statistics dashboard, cleanup UI or automatic fetch tasks. Only the Emby plugin watches local metadata files to refresh affected library items.
- Media is read-only. Exact parent directory names are catalog codes; preserve full prefixes. Invalid/duplicate codes need user correction, appear in the work list's pending group with specific reasons, and cannot be scraped. NFO/images use media filename stems; metadata folders contain only those outputs.
- NFO is authoritative and uncached. Runtime SQLite lives at `/data/runtime/<metadata-path hash>/runtime.sqlite3`, storing indexes, tasks, latest source variants, selections, translation provenance and cooldowns. Keep the service writer lock; no migrations, compatibility aliases, ORM, separate log store or cross-work metadata/translation cache. Settings contain user options only. Emby reads `/caress-metadata` files directly, never SQLite.
- **Fill missing** is the default batch mode: update all automatic fields/images from the first successful source in the current route, preserving manual edits, explicit empty values and manually selected field/image sources. It can replace earlier JavDB output with later successful DMM output. Series is an ordinary editable field. **Refresh** replaces every metadata field, including series, and custom images using the selected source; an absent series clears the old one. Do not replace valid output when fetching, translation or image processing fails.
- Scraping tasks use the configured route; no single-source task or action. Default selection takes the first successful source in user route order; never automatically merge fields or borrow images from another source. Manual field and independent poster/original/sample-group selections are explicit and recorded only in runtime.
- Manual saves use the complete current form, including series and title, as final values. No NFO/candidate fingerprint conflict or extra save confirmation. Preview drafts stay in memory. Keep per-work write locks and atomic writes; handled file-group failures restore original files. Never claim a rollback that did not occur.
- Keep source candidates unmodified. Store processed fields separately, with pinned raw title/plot/actor inputs, pure title text, actor IDs and mapping fingerprints in runtime. Manual saves keep the form's raw snapshots even if newer candidates exist. Preserve originals after editing processed values; NFO contains processed title/plot/actors and the standard originaltitle field. Missing historical originals remain unavailable; no reconstruction or migrations.
- Stage repair uses saved field originals and pinned failed image inputs, never later candidates or refetched successful metadata. Under the same translation configuration, retry only failed fields; changed configuration translates original text again. Cancellation stops workers, keeps records and successful output, and restores work statuses.

## Metadata and sources
- NFO uses caress uniqueid, strict Emby fields and canonical field order shared with forms; genres and tags are separate. Actors contain names only; preserve their source order, with no gender parsing or profiles. Studio is the production maker/brand, never a retailer, distributor, actor agency or inferred current exclusivity. Do not fetch, store or display publisher/label.
- Sources: DMM, JavDB (API then web), JavBus, FC2, AVSOX, AirAV, 1Pondo, Caribbeancom, HEYZO, AVbase. Only default routes place JavDB before JavBus; preserve user order. Search takes the first catalog-valid result in provider ranking; retain DMM's verified search order. Official uncensored sources reject unrelated catalogs without requests. Matching is automatic, with no candidate confirmation or source ambiguity status.
- Use Scrapling first and FlareSolverr for challenges. Reuse network connections and each response's parsed DOM; do not retain unused raw payloads. Up to ten works run concurrently; each source finishes one work before accepting another, while all route sources run concurrently for a work.
- Site intervals apply between works, not search/detail/fallback within one work. Defaults use 1 or multiples of 5; custom intervals accept any finite nonnegative seconds, including fractions, with 0 disabling the interval. The batch's first request starts immediately; later requests share pacing budgets and enforce explicit cooldowns. Cooldowns are keyed by source and request hostname for every source, so separate API/web domains cool independently; site pacing remains shared, and a cooled JavDB API may fall back to its webpage. Source settings automatically refresh cooldown status while visible and expose manual cooldown reset for all domains of a source, effective for active clients without rewriting task history. The reset button's leftmost position aligns its right edge with the site address input; longer status text can push it right, wrapping only when the full row is exhausted. Images share a one-second interval per host.
- Validate translation with benign text before each batch. Configured, valid services translate automatically, with no enable option. Unavailable configured translation fails the affected fields/stage and leaves the work partially complete; unconfigured or unnecessary translation is skipped. One translation request at a time; send only title/description text with the exact prompt, never actor fields, placeholders or script conversion. Remove exact primary/alias names from source titles using the actor JSON, translate the remaining title, then assemble code, actors in source order and translated title separated by spaces, avoiding duplicate code prefixes. Without translation configuration, assemble the cleaned source title. Preserve exact actor names and boundary whitespace in descriptions by translating intervening fragments. Translation provenance keeps originals and configuration fingerprints, including actor rules and title assembly inputs. Tests use benign text only and retain the sample result and duration.
- Use gfriends for portraits in `metadata/actors`, named exactly as NFO actors. Keep one portrait per name. Scraping fetches missing portraits; portrait-update tasks refetch existing portraits without rewriting NFO. Try primary names then safe aliases; retain old portraits on failure. Missing names are normal; ambiguous aliases retain source names without confirmation. Treat actors identically and order their library by work count, portrait availability, then name.
- Actor mappings/rules are JSON only and notice file changes. Key the actor table by JavDB IDs with type/name and optional name_zht/other_name, without a version field. Sort records by (type, ID), one record per line; omit empty optional fields, split comma-separated aliases, remove self-names and deduplicate normalized aliases. Keep raw snapshots outside the repository. Use type 0 for censored and type 1 for uncensored. Scope primary names and aliases by censored/uncensored type first; within that scope primary-name matches take precedence over aliases. Fall back to a globally unique primary name only when the typed lookup has no match. On scraping, write unambiguous Japanese primary names to NFO; fill missing preserves manually edited actors. Mapping changes affect subsequent scraping or explicit remapping tasks, never existing NFO in the background. Remapping uses saved IDs then original names, retains ambiguous names and manual fields, rebuilds automatic titles from saved title text, reuses portraits safely without deleting old files, and never calls sources or translation. Library searches retain existing NFO names as identities.
- Poster crops use bundled licensed YuNet/OpenCV with a center fallback when no face is found. Face detection is for cover cropping, never actor identification or portrait matching. Save fixed 2:3 crops as lossless PNG without resampling; other images retain original bytes. Artwork opens a draggable 2:3 crop editor without an initial selection; face/center actions create it. Poster/original actions say 应用裁剪, sample actions say 设为封面, based only on the clicked group. Applying changes the in-memory draft; one form save writes fields and images together. No uploads.

## Tasks and projections
- Tasks and items are separate; persist the current item without recounting or rewriting the catalog. Task numbers never reuse. Rebuild metadata/status from NFO on restart; keep derived work lookups indexed in memory.
- Batch serialization and per-work write locks are separate. Only running works are locked against editing. Settings saved during a batch apply to the next batch; output-directory changes wait until the queue is idle.
- Task types are fill missing, refresh, portrait updates and actor remapping only. Portrait updates and remapping require selected actors; empty selections never target the full library. Run exactly one task at a time, with up to ten works inside it. Queued tasks may overlap works and read predecessor output when they execute. Scans may run during tasks; retain running work identities and never overwrite a newer write with an older scan snapshot.
- Process phases may be transient; final results remain reviewable. Actionable errors persist until explicitly dismissed and are never cleared by background polling. Expose directory warnings, pending settings and normal portrait misses in their relevant views. Keep current-output problems separate from immutable task results.
- A progress panel belongs to one task. Source status, phase, duration and result/error share one projection with actual execution evidence. Existing NFO, routes, queued items and image events are not metadata-fetch evidence. Unstarted sources show names/actions only; historical variants must fall within the task's timestamps. Explain unavailable details without invented counts, pseudo-status or recovery instructions; omit unknown durations and align durations left.
- Repair reports contain only retried stages; cumulative output health and current-file errors/actions stay outside past-task progress. Preserve actual source summaries in completed records. Poll only active tasks and affected works, update only the saved work after saving, and refresh actors on work/task progress rather than source events.
- Task retry/delete actions belong to the task-list operation column. Active details retain cancellation only. Deleting a completed record requires confirmation and never alters metadata; embedded actions must not navigate rows.

## Interface and maintenance

- Keep UI copy contextual and concise: use noun-only section titles, leave empty metadata fields blank, and omit idle status, repeated context and explanatory placeholders. Show actionable errors, explicit test/save results and relevant pending-state notices.
- Maintain catalog prefixes with `scripts/update_catalog_rules.py` (`fetch` / `build`), retaining raw snapshots and verified movie-type evidence outside the repository. Never infer censorship from the prefix-index record type. Prefer local classification; source evidence fills unknown categories only. Show other and unclassified separately, sharing the catchall route.
- Maintain the actor table with `scripts/update_actor_aliases.py` (`fetch` / `build`); see `scripts/README.md`. Reuse `ApiSettings`, keep raw snapshots outside the repository, and verify deterministic offline output before replacing the bundled JSON. Maintenance scripts are not production runtime resources.
- Works, actors, tasks and settings share segmented navigation, keyboard access and system theme. Tabs provide section names without repeated headings. Product/version belong in the footer. Use shared Select, Checkbox, table/title and metadata-field renderers; whole rows open details independently of embedded controls. Disable unavailable actions and lazy-load optional editors.
- Work lists, task-detail work lists and actor lists support list/grid views, with five grid columns on desktop and fewer on narrow screens. Reuse the work-list renderer between works and tasks, and share selection controls between works and actors.
- Details place artwork before metadata, following canonical NFO field order. Title and plot show an editable processed field with a noninteractive 译 badge followed by its read-only original; actors use a matching 主名 badge followed by original names. Both source selectors in each pair switch together. When original and processed actor names are identical, show one actor field without the 主名 badge. Show last progress timestamp beside code/status. Use two expanded columns (images/metadata to progress 2:1), thumbnail grids, grouped cropped/original covers and four-column still grids. All source cards stay inside progress; no NFO-availability label or repeated completed message. Settings stay expanded. Preserve the last successful actor list across tab switches; initial loading must not flash a placeholder count.
- Lists use shared 14px text; summary counts 16px with a space before Chinese units; settings heading hierarchy 18/16/14px. Chinese UI names use 2–6 characters and descriptions at most 20. Use 扫描作品 and 刮削元数据; preserve protocol identifiers. Dates use 年月日; work progress uses YYYY/MM/DD.
- Branding uses two asymmetric solid wings framing a feminine profile in negative space, without outlines. Use graphite on light backgrounds and warm ivory on dark backgrounds, with transparency. The web favicon SVG is the project icon; Emby embeds a transparent 640×360 warm-ivory PNG via IHasThumbImage. Interface icons follow the system theme.
- Fix confirmed problems where responsibility belongs; do not add layers for tidiness. Remove redundant state, dead parameters and compatibility branches. Shared controls own common styling. Comments explain boundaries, reasons and necessary tradeoffs, not change history. Preserve real metadata and keep backups outside the repository.
